## 项目概述

AetherFlow是一款Chrome浏览器扩展，旨在帮助用户优化与管理AI提示词。该产品允许用户快速调用存储的提示词、建立个人提示词库，并通过大语言模型API分析和改进提示词质量。本文档提供了AetherFlow项目的完整实现指南，包括产品需求、用户流程、UI设计、系统架构、数据库设计、API接口、前后端架构、环境配置、编码规范、测试策略和技术栈等方面的详细规划。

作为一个小型敏捷开发项目，本文档注重实用性和有效性，为AI编程员提供清晰的开发蓝图。

## 1. 产品需求

### 1.1 核心功能

#### 1.1.1 提示词快捷输入 (优先级：P0)
- 允许用户通过"/"快捷指令在AI平台输入框中快速调用已保存的提示词
- 支持关键词实时搜索和自动联想
- 联想结果按"收藏>高频使用>低频使用"排序
- 最多显示10个匹配结果

#### 1.1.2 提示词库 (优先级：P0)
- 在扩展侧边栏以卡片形式展示已存储和已收藏的提示词
- 支持关键词搜索、多种排序方式（使用次数、收藏状态、存储时间）
- 卡片详情面板包含复制按钮
- 支持侧边栏宽度调整、最小化/最大化切换

#### 1.1.3 提示词优化 (优先级：P1)
- 通过大语言模型API分析和改进提示词质量
- 用户界面提供输入框和优化按钮
- 支持多级优化链，用户可基于任意版本继续优化
- 优化结果以卡片形式展示，支持收藏、复制和手动编辑
- 支持将优化结果添加至提示词库

### 1.2 用户模式

#### 1.2.1 轻量级模式 (优先级：P0)
- 用户无需注册登录即可使用核心功能
- 数据仅存储在本地浏览器中，不进行云端同步
- 本地存储的提示词数量上限为50条
- 达到存储上限时，系统会提示用户需要删除一些提示词或升级到完整账户模式

#### 1.2.2 完整账户模式 (优先级：P1)
- 支持用户注册、登录和账户管理
- 提供跨设备数据同步功能
- 无提示词数量限制

### 1.3 功能限制和配额

- 优化卡片数量上限为10张（单个优化会话最多保存10个版本，用户同时只能有一个优化会话）
- 轻量级模式下本地存储上限为50条提示词
- 提示词优化API调用频率限制：每用户每小时20次


## 2. 用户流程

### 2.1 轻量级使用流程

1. **安装扩展**
   - 用户从Chrome商店安装AetherFlow扩展
   - 系统默认进入轻量级模式，数据存储在本地

2. **提示词快捷输入**
   - 用户在AI平台输入框中输入"/"字符
   - 系统显示下拉菜单，展示可用提示词
   - 用户输入关键词进行过滤
   - 用户选择提示词并确认，系统将完整提示词插入输入框

3. **提示词库使用**
   - 用户点击扩展图标或快捷键(Ctrl+Shift+E)打开侧边栏
   - 用户点击"提示词库"选项卡
   - 用户浏览、搜索、排序提示词
   - 用户点击卡片上的复制按钮，可复制提示词内容

4. **提示词优化**
   - 用户点击"提示词优化"选项卡
   - 用户输入原始提示词并点击"优化"按钮
   - 系统调用API并展示优化结果
   - 用户可继续优化、编辑、收藏或复制结果

### 2.2 账户操作流程

1. **用户注册/登录**
   - 用户点击侧边栏顶部的"登录"按钮
   - 系统显示登录/注册表单
   - 用户完成身份验证
   - 系统升级为完整账户模式

2. **数据同步**
   - 用户登录后，系统自动启动数据同步
   - 本地数据与云端数据合并
   - 系统显示同步状态指示器

3. **轻量级模式转换**
   - 系统检测本地数据与云端数据的冲突
   - 系统提供合并选项：保留本地版本、云端版本或两者合并
   - 冲突解决UI参考常见云存储服务实现（如OneDrive），显示冲突项目并允许用户逐项选择或批量应用解决方案

## 3. UI组件设计映射

### 3.1 导航组件（Navigation）

- **位置**：侧边栏顶部
- **结构**：
  - 居中导航项（提示词库、提示词优化）
  - 右侧用户状态/登录按钮
- **交互**：点击切换页面

### 3.2 提示词库组件（PromptLibrary）

- **位置**：侧边栏主体区域
- **结构**：
  - 顶部搜索栏
  - 排序控件（使用频率/收藏/时间）
  - 卡片网格布局
  - 卡片包含：提示词内容预览、复制按钮
  - 卡片详情面板：完整内容、复制按钮
- **交互**：
  - 点击卡片显示详情
  - 点击复制按钮执行对应操作

### 3.3 提示词优化组件（PromptOptimizer）

- **位置**：侧边栏主体区域
- **结构**：
  - 顶部输入框
  - 优化按钮
  - 优化结果展示区域
  - 优化卡片：版本标识、内容预览、继续优化按钮、收藏按钮、复制按钮
- **交互**：
  - 点击优化按钮启动优化
  - 点击卡片显示完整内容
  - 点击继续优化按钮基于当前版本优化
  - 点击收藏/复制按钮执行对应操作
  - 点击收藏按钮将优化结果添加至提示词库
  - 支持卡片拖拽至提示词库图标将优化结果添加至提示词库

### 3.4 快捷指令组件（QuickCommand）

- **位置**：AI平台输入框上方
- **结构**：
  - 下拉菜单
  - 匹配项列表
  - 关键词高亮显示
- **交互**：
  - 键盘上下键选择
  - 回车键确认选择
  - 点击选项确认选择

### 3.5 用户状态组件（UserStatus）

- **位置**：侧边栏顶部右侧
- **结构**：
  - 登录前：登录按钮
  - 登录后：用户头像、同步状态指示器
- **交互**：
  - 点击登录按钮显示登录表单
  - 点击用户头像显示用户菜单

## 4. 系统架构设计

### 4.1 整体架构

```
+------------------+        +------------------+        +-------------------+
|                  |        |                  |        |                   |
| Chrome扩展组件   |<------>| 后端API服务      |<------>| 大语言模型API     |
|                  |        |                  |        |                   |
+------------------+        +------------------+        +-------------------+
        ^                          ^
        |                          |
        v                          v
+------------------+        +------------------+
|                  |        |                  |
| 本地存储         |        | 云数据库         |
|                  |        |                  |
+------------------+        +------------------+
```

### 4.2 组件说明

#### 4.2.1 Chrome扩展组件
- **背景脚本（Background Script）**：管理扩展生命周期、处理跨页面通信
- **内容脚本（Content Script）**：注入AI平台页面，实现快捷指令功能
- **侧边栏（Sidebar）**：提供提示词库和提示词优化功能，作为Chrome提供的侧边栏扩展实现
- **弹出页面（Popup）**：可选组件，提供快速访问设置的入口，如果侧边栏功能足够完善可不必实现

#### 4.2.2 后端API服务
- **优化服务**：处理提示词优化请求，调用大语言模型API
- **账户服务**：管理用户注册、登录和认证
- **同步服务**：处理数据同步和冲突解决
- **配额管理**：控制API调用频率和限制

#### 4.2.3 存储系统
- **本地存储**：使用Chrome Storage API存储轻量级模式数据
- **云数据库**：存储用户账户和完整模式数据

#### 4.2.4 外部依赖
- **大语言模型API**：提供提示词优化能力（OpenAI GPT或同等服务）
- **身份验证服务**：可选，用于用户认证（如Firebase Auth）

#### 4.2.5 内容脚本注入策略
为了确保跨平台兼容性，内容脚本需要智能识别和适配不同的AI平台：

- **平台识别机制**：基于URL模式和DOM特征识别当前AI平台
- **适配器模式**：为每个支持的平台（如ChatGPT、Claude、Bard等）实现专用适配器
- **匹配规则配置**：
  ```json
  // manifest.json 内容脚本配置示例
  "content_scripts": [
    {
      "matches": ["*://chat.openai.com/*"],
      "js": ["content/index.js", "content/platforms/chatgpt.js"]
    },
    {
      "matches": ["*://claude.ai/*"],
      "js": ["content/index.js", "content/platforms/claude.js"]
    }
  ]
  ```
- **降级策略**：对于未明确支持的平台，提供基本功能或友好提示

#### 4.2.6 扩展权限管理
遵循最小权限原则，manifest.json中仅请求必要权限：

```json
"permissions": [
  "storage",          // 用于本地数据存储
  "sidePanel",        // 用于侧边栏功能
  "activeTab",        // 用于与当前标签页交互
  "scripting"         // 用于动态脚本注入
],
"host_permissions": [
  "*://chat.openai.com/*",
  "*://claude.ai/*",
  // 其他支持的AI平台URL
],
"optional_permissions": [
  "identity"          // 仅在用户选择账户同步时请求
]
```

### 4.3 数据流

1. **提示词快捷输入**
   - 内容脚本 → 本地存储/云数据库 → 内容脚本 → AI平台输入框

2. **提示词库操作**
   - 侧边栏 → 本地存储/云数据库 → 侧边栏

3. **提示词优化**
   - 侧边栏 → 后端API → 大语言模型API → 后端API → 侧边栏

4. **数据同步**
   - 本地存储 → 后端API → 云数据库 → 后端API → 本地存储

### 4.4 离线支持策略

为确保核心功能在无网络环境下仍可使用，实现以下离线支持机制：

1. **功能降级方案**：
   - **P0级功能**（提示词库、快捷输入）：完全离线可用
   - **P1级功能**（提示词优化、账户同步）：仅在在线时可用，离线时显示适当提示

2. **本地缓存策略**：
   - 使用IndexedDB作为备用存储，提供更大存储容量
   - 缓存最近使用的提示词优化结果

3. **离线状态检测与提示**：
   - 实现网络状态监听
   - 离线时显示状态指示器，并自动禁用依赖网络的功能

4. **同步恢复机制**：
   - 记录离线期间的操作日志
   - 网络恢复后自动执行同步

## 6. API设计

### 6.1 后端API端点

#### 6.1.1 提示词优化API

```
POST /api/prompts/optimize
```

**请求体**：
```json
{
  "content": "需要优化的提示词内容",
  "parentId": "可选，父版本ID",
  "sessionId": "优化会话ID",
  "optimizationLevel": "standard|creative|concise"
}
```

**响应**：
```json
{
  "success": true,
  "data": {
    "id": "优化版本ID",
    "content": "优化后的内容",
    "parentId": "父版本ID",
    "version": 1,
    "createdAt": "创建时间"
  }
}
```

#### 6.1.2 用户认证API

```
POST /api/auth/register
```

**请求体**：
```json
{
  "email": "用户邮箱",
  "password": "用户密码"
}
```

**响应**：
```json
{
  "success": true,
  "data": {
    "token": "JWT令牌",
    "user": {
      "id": "用户ID",
      "email": "用户邮箱"
    }
  }
}
```

```
POST /api/auth/login
```

**请求体**：
```json
{
  "email": "用户邮箱",
  "password": "用户密码"
}
```

**响应**：与注册响应相同

#### 6.1.3 数据同步API

```
GET /api/sync/prompts
```

**请求参数**：
```
lastSyncAt: ISO日期字符串
```

**响应**：

   ```jsx
       this.state = { hasError: false, error: null };

       }
       return this.props.children;
     }
   }
   ```

### 7.5 业务逻辑分层

AetherFlow采用清晰的业务逻辑与展示逻辑分离策略，通过服务层（Service Layer）模式实现业务逻辑的集中管理和接口暴露。

#### 7.5.1 服务层设计

- **服务模块组织**：
  - 每个业务领域有独立的服务模块（如提示词服务、认证服务）
  - 服务模块内部包含接口定义、类型定义和具体实现

- **接口暴露模式**：
  - 每个服务模块通过index.js统一导出接口，隐藏实现细节
  - 消费者只能访问公开接口，无法直接调用内部实现

#### 7.5.2 业务逻辑分类

- **数据访问服务**：处理存储和检索操作
  - `storage` 服务：提供本地数据存储和加载功能
  - `sync` 服务：处理数据同步和冲突解决

- **功能服务**：实现核心业务功能
  - `prompt` 服务：提示词管理功能
  - `optimize` 服务：提示词优化功能
  - `auth` 服务：用户认证功能

- **基础服务**：提供底层功能支持
  - `messaging` 服务：处理扩展内部通信
  - `platform` 服务：处理平台特定功能

#### 7.5.3 服务调用模式

- **直接调用**：服务之间可以相互调用，处理依赖关系
- **通过Hooks调用**：UI组件通过自定义Hooks调用服务
- **消息驱动调用**：跨进程组件（如背景脚本与内容脚本）通过消息机制调用服务

```javascript
// 提示词优化服务实现示例
class PromptService {
  async optimizePrompt(content, parentId, sessionId, level, userId = null) {
    // 1. 验证输入参数
    this.validateInput(content);
    
    // 2. 检查优化次数限制（仅对已登录用户）
    if (userId) {
      await this.checkRateLimit(userId);
    } else {
      // 轻量级模式使用IP或设备标识符进行频率限制
      await this.checkAnonymousRateLimit(getClientIdentifier());
    }
    
    // 3. 调用大语言模型服务
    const optimizedContent = await llmService.optimize(content, level);
    
    // 4. 保存优化结果
    const optimizationResult = await this.saveOptimization(
      content, 
      optimizedContent, 
      parentId, 
      sessionId,
      userId
    );
```

### 10.1 通用规范
