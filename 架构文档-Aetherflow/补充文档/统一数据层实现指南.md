# 统一数据层实现指南

本文档为任务2.0.1"统一数据层实现"提供全面指南，包括问题分析、设计方案和实施策略，旨在解决当前存在的数据同步问题，并为后续功能开发提供坚实的基础设施。

## 1. 问题背景与分析

### 1.1 问题现象

在AetherFlow项目开发过程中，我们发现存在一个明显的数据不一致问题：

- **侧边栏数据**：来自`usePrompts` hook，基于`mock.ts`中定义的模拟数据
- **快捷输入联想框数据**：来自`background/index.ts`中定义的另一套硬编码数据

这导致用户在侧边栏管理的提示词无法在快捷输入中显示，反之亦然，严重影响了用户体验。

### 1.2 技术原因分析

此问题的技术根源在于Chrome扩展特有的架构限制：

1. **多上下文环境**：Chrome扩展包含多个独立的JavaScript执行环境
   - Background Script (Service Worker)：后台常驻脚本
   - Content Script：注入到网页的脚本
   - Side Panel：侧边栏UI

2. **内存隔离**：这些环境有各自独立的内存空间，无法直接共享变量

3. **当前实现问题**：
   - 开发者为快速实现原型，在各环境中使用了独立的数据源
   - 没有建立数据同步机制，导致数据不一致
   - 没有明确谁负责实现共享数据基础设施

4. **内容安全策略限制**：
   - 遇到了与`eval()`相关的CSP错误
   - 需要严格遵循Chrome扩展的安全要求

### 1.3 目标愿景

建立一个统一、安全、可扩展的数据层，具备以下特性：

- **单一数据源**：所有组件使用同一数据存储
- **跨环境通信**：支持各执行环境间的数据同步
- **安全合规**：符合Chrome扩展的内容安全策略
- **向后兼容**：支持现有功能平稳过渡
- **面向未来**：为后续功能（如云同步、提示词优化）提供基础

### 2.2 存储层设计

采用Chrome Storage API作为统一存储机制：

```typescript
// services/storage/types.ts
export interface Prompt {
  id: string;
  content: string;
  title?: string;
  createdAt: string;
  updatedAt: string;
  isFavorite: boolean;
  useCount: number;
  lastUsed?: string;
}

export interface StorageService {
  // 提示词相关操作
  getPrompt(id: string): Promise<Prompt | null>;
  getAllPrompts(): Promise<Prompt[]>;
  savePrompt(prompt: Prompt): Promise<void>;
  updatePrompt(id: string, updates: Partial<Prompt>): Promise<void>;
  deletePrompt(id: string): Promise<void>;
  incrementUseCount(id: string): Promise<void>;
  
  // 通用存储操作
  get<T>(key: string): Promise<T | null>;
  set<T>(key: string, value: T): Promise<void>;
  remove(key: string): Promise<void>;
  clear(): Promise<void>;
}
```

实现关键点：

1. **键名策略**：使用前缀区分不同类型数据（如`prompt_`、`setting_`）
2. **批量操作**：优化读写性能，减少存储API调用
3. **错误处理**：统一处理存储配额和权限问题
4. **数据迁移**：支持版本化数据格式，确保向后兼容

具体实现示例：

```typescript
// services/storage/chromeStorage.ts
export const chromeStorageService: StorageService = {
  async getPrompt(id: string) {
    const result = await chrome.storage.local.get(`prompt_${id}`);
    return result[`prompt_${id}`] || null;
  },
  
  async getAllPrompts() {
    const result = await chrome.storage.local.get(null);
    return Object.entries(result)
      .filter(([key]) => key.startsWith('prompt_'))
      .map(([_, value]) => value as Prompt);
  },
  
  async savePrompt(prompt: Prompt) {
    if (!prompt.id) {
      throw new Error('Prompt ID is required');
    }
    
    // 确保所有必要字段存在
    const now = new Date().toISOString();
    const completePrompt: Prompt = {
      ...prompt,
      createdAt: prompt.createdAt || now,
      updatedAt: now,
      useCount: prompt.useCount || 0,
      isFavorite: Boolean(prompt.isFavorite)
    };
    
    return chrome.storage.local.set({
      [`prompt_${prompt.id}`]: completePrompt
    });
  },
  
  // 其他方法实现...
};
```

### 2.3 通信层设计

实现基于`chrome.runtime.sendMessage`的安全消息机制：

```typescript
// services/messaging/types.ts
export type MessageType = 
  | 'GET_PROMPTS' 
  | 'GET_PROMPT' 
  | 'SAVE_PROMPT'
  | 'UPDATE_PROMPT'
  | 'DELETE_PROMPT'
  | 'INCREMENT_USE_COUNT';

export interface Message<T = any> {
  type: MessageType;
  payload?: T;
  requestId?: string; // 用于跟踪请求-响应
}

export interface MessageResponse<T = any> {
  success: boolean;
  data?: T;
  error?: string;
  requestId?: string;
}

// services/messaging/index.ts
export const messagingService = {
  send<T, R>(message: Message<T>): Promise<R> {
    return new Promise((resolve, reject) => {
      const requestId = Date.now().toString() + Math.random().toString().slice(2);
      const messageWithId = { ...message, requestId };
      
      const timeout = setTimeout(() => {
        reject(new Error(`Message timeout: ${message.type}`));
      }, 5000);
      
      chrome.runtime.sendMessage(messageWithId, (response: MessageResponse<R>) => {
        clearTimeout(timeout);
        if (chrome.runtime.lastError) {
          return reject(chrome.runtime.lastError);
        }
        
        if (!response.success) {
          return reject(new Error(response.error || 'Unknown error'));
        }
        
        resolve(response.data as R);
      });
    });
  },
  
  listen<T, R>(type: MessageType, handler: (payload: T) => Promise<R>): void {
    chrome.runtime.onMessage.addListener((message: Message<T>, sender, sendResponse) => {
      if (message.type !== type) return false;
      
      handler(message.payload as T)
        .then(result => {
          sendResponse({
            success: true,
            data: result,
            requestId: message.requestId
          });
        })
        .catch(error => {
          sendResponse({
            success: false,
            error: error.message,
            requestId: message.requestId
          });
        });
      
      return true; // 表示将异步发送响应
    });
  },
  
  broadcast<T>(message: Message<T>): void {
    chrome.runtime.sendMessage(message);
    chrome.tabs.query({}, tabs => {
      tabs.forEach(tab => {
        if (tab.id) {
          chrome.tabs.sendMessage(tab.id, message);
        }
      });
    });
  }
};
```

实现关键点：

1. **类型安全**：完整的TypeScript类型支持
2. **请求跟踪**：使用唯一requestId关联请求和响应
3. **错误传播**：确保错误正确传递和处理
4. **超时机制**：处理无响应情况
5. **权限控制**：确保消息安全性

### 2.4 集成层设计

提供React Hooks连接UI与数据层：

```typescript
// hooks/usePrompts.ts
export function usePrompts() {
  const [prompts, setPrompts] = useState<Prompt[]>([]);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState<Error | null>(null);
  
  useEffect(() => {
    let mounted = true;
    
    const loadPrompts = async () => {
      try {
        setLoading(true);
        
        // 在侧边栏环境中直接使用存储服务
        // 在内容脚本中使用消息服务
        const data = isExtensionContext() 
          ? await storageService.getAllPrompts()
          : await messagingService.send({ type: 'GET_PROMPTS' });
        
        if (mounted) {
          setPrompts(data);
          setError(null);
        }
      } catch (err) {
        if (mounted) {
          setError(err instanceof Error ? err : new Error(String(err)));
        }
      } finally {
        if (mounted) {
          setLoading(false);
        }
      }
    };
    
    loadPrompts();
    
    // 监听提示词变更事件
    const handlePromptChange = () => {
      loadPrompts();
    };
    
    // 添加事件监听
    eventEmitter.on('PROMPT_CHANGED', handlePromptChange);
    
    return () => {
      mounted = false;
      eventEmitter.off('PROMPT_CHANGED', handlePromptChange);
    };
  }, []);
  
  const addPrompt = async (content: string) => {
    try {
      const newPrompt: Partial<Prompt> = {
        id: uuidv4(),
        content,
        title: extractTitle(content),
        isFavorite: false,
        useCount: 0
      };
      
      // 乐观更新UI
      setPrompts(prev => [...prev, newPrompt as Prompt]);
      
      // 持久化存储
      await storageService.savePrompt(newPrompt as Prompt);
      
      // 广播变更事件
      eventEmitter.emit('PROMPT_CHANGED');
      
      return newPrompt;
    } catch (err) {
      // 失败时回滚UI
      setPrompts(prev => prev.filter(p => p.id !== newPrompt.id));
      throw err;
    }
  };
  
  // 其他操作...
  
  return {
    prompts,
    loading,
    error,
    addPrompt,
    // 其他操作...
  };
}
```

实现关键点：

1. **统一接口**：为UI组件提供一致的数据访问接口
2. **状态管理**：处理加载、错误等状态
3. **实时更新**：监听数据变化，确保UI同步
4. **乐观更新**：提升用户体验
5. **错误恢复**：提供错误恢复机制

## 3. 现有模块迁移与模拟数据支持

### 3.1 现有使用Mock数据的组件处理

当前项目中多个组件和功能模块直接内联使用mock数据，这些组件在重构过程中需要特殊处理：

1. **识别模拟数据依赖**：
   - 扫描并识别所有直接引用`mock.ts`或内联硬编码数据的组件
   - 记录每个组件的依赖方式和数据使用模式
   - 对比mock数据结构与实际数据模型的差异

2. **渐进式替换策略**：
   - 保留原有组件功能，在内部实现替换为统一数据源
   - 使用适配器模式连接旧接口与新数据服务
   - 组件接口保持向后兼容，减少破坏性变更

3. **具体实现步骤**：
   ```javascript
   // 以提示词库组件为例的迁移方式
   // 原有实现
   import { mockPrompts } from '../../mock';
   
   function PromptLibrary() {
     const [prompts, setPrompts] = useState(mockPrompts);
     // 组件逻辑...
   }
   
   // 迁移后实现
   import { usePrompts } from '../../hooks/usePrompts';
   
   function PromptLibrary() {
     // 使用新的统一数据层hook
     const { prompts, loading, error } = usePrompts();
     
     // 增加loading和error处理
     if (loading) return <Loading />;
     if (error) return <ErrorDisplay error={error} />;
     
     // 保持原有组件UI和交互逻辑不变
     // ...
   }
   ```

4. **验证与回滚机制**：
   - 为每个迁移的组件添加A/B测试开关
   - 在出现问题时能够快速回退到使用mock数据
   - 实现UI一致性自动化比对测试

   ```typescript
   // services/migration/dataMigration.ts
   import { getOldMockData } from '../../mock';
   import { storageService } from '../storage';
   import { mapOldPromptToNew } from '../../utils/dataMapping';
   
   // 将旧数据迁移到新存储系统
   export async function migrateExistingData() {
     try {
       // 获取旧数据
       const oldData = getOldMockData();
       
       // 转换为新格式
       const newPrompts = oldData.map(mapOldPromptToNew);
       
       // 批量保存到新存储
       await Promise.all(newPrompts.map(prompt => 
         storageService.savePrompt(prompt)
       ));
       
       return {
         success: true,
         migratedCount: newPrompts.length
       };
     } catch (error) {
       console.error('Data migration failed:', error);
       return {
         success: false,
         error
       };
     }
   }
   ```

## 5. 代码规范与最佳实践

### 5.1 命名规范

- **文件命名**：
  - 服务模块：使用camelCase（如`storageService.ts`）
  - 类型定义：使用camelCase（如`messageTypes.ts`）
  - 测试文件：使用原文件名加`.test`（如`storageService.test.ts`）

- **变量命名**：
  - 服务实例：使用camelCase（如`storageService`）
  - 类型和接口：使用PascalCase（如`StorageService`）
  - 常量：使用UPPER_SNAKE_CASE（如`DEFAULT_TIMEOUT`）

### 5.2 安全最佳实践

- 避免使用`eval()`和`new Function()`
- 使用内置API代替不安全的替代方案
- 遵循最小权限原则
- 验证所有数据输入
- 处理所有异常情况

### 5.3 性能最佳实践

- 批量处理Chrome Storage操作
- 实现内存缓存减少API调用
- 防止不必要的重渲染
- 优化大数据集的处理
- 使用防抖和节流技术

### 5.4 文档规范

- 为所有公共API提供详细JSDoc
- 创建架构图和数据流图
- 记录设计决策和权衡
- 提供使用示例和教程
- 更新架构文档保持一致性
