# Aetherflow 统一数据层架构

## 1. 概述

Aetherflow 统一数据层是为了解决在不同环境（扩展背景页、内容脚本、侧边栏等）之间共享和管理提示词数据而设计的架构。它提供了一致的接口和API，使得在任何环境中都可以无缝地访问和操作数据。

## 2. 系统架构

整个数据层分为四个主要部分：

### 2.1 存储层 (Storage Layer)

- **接口定义**：`StorageService` 接口统一定义了数据存储和检索的方法
- **实现**：
  - `ChromeStorageService`：基于Chrome Storage API的实现，用于持久化数据
  - `MockStorageService`：内存存储实现，用于开发和测试环境

### 2.2 通信层 (Communication Layer)

- **消息定义**：统一的消息类型和接口
- **发送机制**：跨环境通信实现
- **监听机制**：消息处理和路由
- **错误处理**：超时和异常管理

### 2.3 集成层 (Integration Layer)

- **消息处理器**：与存储层的集成
- **React 钩子**：`usePromptsData` 提供了对数据的访问和操作
- **环境检测**：自动适应不同运行环境

### 2.4 兼容层 (Compatibility Layer)

- **旧API兼容**：支持旧版消息格式
- **示例数据**：初次安装时的数据初始化
- **迁移辅助**：数据结构转换

## 5. 使用方法

### 5.1 在React组件中使用

```jsx
import { usePromptsData } from '../hooks/usePromptsData';

function PromptList() {
  const { 
    prompts, 
    loading, 
    addPrompt, 
    updatePrompt,
    deletePrompt, 
    toggleFavorite, 
    incrementUseCount 
  } = usePromptsData();

  if (loading) return <div>加载中...</div>;

  return (
    <div>
      {prompts.map(prompt => (
        <div key={prompt.id}>
          <h3>{prompt.title}</h3>
          <p>{prompt.content}</p>
          <button onClick={() => toggleFavorite(prompt.id)}>
            {prompt.isFavorite ? '取消收藏' : '收藏'}
          </button>
          <button onClick={() => incrementUseCount(prompt.id)}>
            使用 ({prompt.useCount || 0})
          </button>
          <button onClick={() => deletePrompt(prompt.id)}>删除</button>
        </div>
      ))}
    </div>
  );
}
```

### 5.2 在非React环境中使用

```typescript
import { storageService } from '../services/storage';
import { sendMessage } from '../services/messaging';
import { isExtensionContext } from '../utils/environment';

async function getAndProcessPrompts() {
  try {
    if (isExtensionContext()) {
      // 在扩展环境中直接使用存储服务
      const prompts = await storageService.getAllPrompts();
      // 处理数据...
    } else {
      // 在内容脚本中使用消息通信
      const prompts = await sendMessage({ type: 'GET_PROMPTS' });
      // 处理数据...
    }
  } catch (error) {
    console.error('获取提示词失败', error);
  }
}
```

## 6. 最佳实践

1. **统一数据访问**：始终使用 `usePromptsData` 钩子或存储服务API访问数据，避免直接操作
2. **实时更新**：利用钩子的自动更新功能，无需手动刷新
3. **错误处理**：所有API都支持错误捕获，确保在UI中提供适当的错误反馈
4. **分页加载**：对于大量数据，使用搜索API的分页功能
5. **批量操作**：尽量减少更新操作次数，提高性能

## 7. 迁移指南

从旧版API迁移到统一数据层：

1. 将导入从 `import { usePrompts } from '../hooks/usePrompts'` 更改为 `import { usePromptsData } from '../hooks/usePromptsData'`
2. 更新方法名：
   - `incrementPromptUse` -> `incrementUseCount`
   - 搜索方法现在接受 `PromptFilter` 对象而不是字符串
3. 使用更新后的Prompt类型定义：`import { Prompt } from '../services/prompt/types'`

## 8. 故障排除

- **数据不同步**：确保所有环境中的存储版本一致，可以使用 `refresh()` 方法强制重新加载
- **消息超时**：检查后台页是否正常运行，可能需要重启扩展
- **存储错误**：检查Chrome存储配额是否已满
